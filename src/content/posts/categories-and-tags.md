分类和标签决定文章如何被发现。当前博客把分类页作为主题浏览入口，把归档页保留给时间线浏览，这样读者可以按主题或时间两种方式进入内容。

## 分类规则

每篇文章只设置一个 `category`。当前项目已配置的规范分类包括：

| 分类 | 用途 |
| --- | --- |
| 博客技术 | 当前博客系统的功能说明、写作规范、内容维护和发布输出 |
| 技术 | 工程、框架、架构和实现细节 |
| 前端 | UI、交互、样式和浏览器相关内容 |
| 随笔 | 非教程型思考和记录 |
| 生活 | 个人生活内容 |
| 学习 | 学习过程和资料整理 |
| 工作 | 工作流、协作和实践记录 |
| 教程 | 可复用的操作说明 |

新文章优先使用这些分类，不要临时创造含义相近的新分类。

## 标签规则

标签用于补充分类。分类回答“这篇文章主要属于哪里”，标签回答“它还涉及哪些关键词”。

建议标签控制在 2 到 5 个。技术名词可以保留英文，例如 `Astro`、`Svelte`、`Markdown`；普通主题优先使用中文，例如 `分类`、`内容组织`。

## 分类页

分类根路径是 `/category/{slug}/`。这是分类第一页，也是分类和标签筛选的主入口。

分类分页从 `/category/{slug}/page/2/` 开始，不生成 `/page/1/`。文章卡片和文章详情中的分类链接都指向分类根路径。

## Tag 筛选

文章标签链接会进入所属分类下的查询模式，例如：

```text
/category/blog-tech/?tag=markdown
```

浏览器会在需要时加载对应分类的 Tag 索引，然后在同一页面内完成筛选。这样普通分类页不需要一次性携带全部文章数据。

## 维护建议

新增文章前先检查已有分类和标签。内容系统会处理 slug，但维护者仍应保持命名一致，避免读者看到多个含义相同的入口。
